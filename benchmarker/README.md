# Revera Benchmarker

Large-scale benchmark suite that tests Revera against **100k+ npm packages** in parallel, stores all results, and produces rich comparison reports.

## Directory Layout

```
benchmarker/
├── benchmark.sh            # Thin orchestrator — run this
├── package.json
├── tsconfig.json
├── datasets/
│   ├── known-trusted.jsonl  # ~300 seed packages (ground-truth: trusted)
│   ├── known-malicious.jsonl# ~60 seed packages  (ground-truth: malicious/typosquat)
│   └── npm.jsonl            # 100k+ generated by fetch-dataset (gitignored)
├── scripts/
│   └── fetch-dataset.ts     # Populates npm.jsonl from npm APIs
└── src/
    ├── types.ts             # Shared types
    ├── runner.ts            # Main orchestrator (main thread)
    ├── worker.ts            # Worker thread (one per --workers)
    ├── checkpoint.ts        # Resume-safe checkpoint read/write
    ├── compare.ts           # Cross-run comparison
    └── report.ts            # HTML report generator
```

## Quick Start

### 1. Fetch the dataset (once)

```bash
cd benchmarker
npm install
npm run fetch-dataset
# → writes datasets/npm.jsonl  (~100k+ lines, may take ~10 min)
```

### 2. Run the benchmark

```bash
chmod +x benchmark.sh
./benchmark.sh --workers 16
```

That single command:
1. Clones revera into a temp dir (`/tmp/revera-build-XXXXXX`)
2. Runs `pnpm install && pnpm build` on the clone
3. Compiles the benchmarker TypeScript
4. Runs N parallel workers against every package in the dataset
5. Streams results to `~/revera_benchmarks/<run-id>/results.jsonl`
6. Compares to the previous run (if one exists)
7. Generates `report.html`, `summary.json`, `metadata.json`
8. Deletes the temp clone

## Options

| Flag | Default | Description |
|------|---------|-------------|
| `--workers N` | `nproc` | Number of parallel workers |
| `--dataset PATH` | `datasets/npm.jsonl` | JSONL dataset file |
| `--output-dir DIR` | `~/revera_benchmarks` | Where results are saved |
| `--threshold N` | `60` | Score ≥ threshold → predicted "trusted" |
| `--branch NAME` | `main` | Branch to clone and test |
| `--repo URL` | GitHub upstream | Override repo URL |
| `--resume RUN_ID` | *(none)* | Resume a crashed run |

Environment overrides: `REVERA_REPO`, `REVERA_BRANCH`, `WORKERS`, `OUTPUT_DIR`

## Output Structure

Every run creates a self-contained directory:

```
~/revera_benchmarks/
└── 2026-07-06T18-32-14/
    ├── metadata.json    # run info: commit, branch, host, timing, config
    ├── summary.json     # aggregated stats: accuracy, F1, latency percentiles
    ├── results.jsonl    # one JSON line per package (all 100k+)
    ├── comparison.json  # delta vs previous run (regressions, improvements)
    ├── checkpoint.txt   # completed package keys (enables --resume)
    └── report.html      # self-contained HTML report (open in browser)
```

Past runs are **never deleted or overwritten**.  
Comparison always diffs the current run against the most-recent previous run.

## Dataset Format

Each line in a JSONL dataset file:

```json
{"registry":"npm","name":"lodash","version":"4.17.21","label":"trusted"}
```

| Field | Values |
|-------|--------|
| `registry` | `npm` \| `pypi` \| `crates` \| `go` |
| `name` | Package name |
| `version` | *(optional)* specific version |
| `label` | `trusted` \| `malicious` \| `typosquat` \| `suspicious` \| `unknown` |

- **Labeled** packages (`trusted`, `malicious`, etc.) contribute to **accuracy** stats.
- **Unknown** packages are benchmarked for **throughput / stability** only.

---

## Resuming a Crashed Run

If a run crashes at 80,000 / 100,000:

```bash
./benchmark.sh --resume 2026-07-06T18-32-14
```

Workers skip all keys already in `checkpoint.txt` and continue from where they left off. No package is processed twice.

## How Parallelism Works

```
SharedArrayBuffer(Int32)  ← atomic counter
        │
  ┌─────┼─────┬──────┬──────┐
  │     │     │      │      │
Worker Worker Worker Worker Worker ...
  │     │     │      │      │
  └──── Atomics.add(counter, 0, 1) ────►  next package index
```

Each worker atomically increments a shared counter to claim the next package.  
**No static slicing** — if one package is slow, other workers aren't blocked.

## Score Classification

| Score | Predicted |
|-------|-----------|
| ≥ threshold (default 60) | `trusted` → category `safe` |
| ≥ threshold × 0.55 | `suspicious` → category `risky` |
| < threshold × 0.55 | `malicious` → category `risky` |

**False positive**: label=`trusted`, predicted=`risky`  
**False negative**: label=`malicious`/`typosquat`/`suspicious`, predicted=`safe`
